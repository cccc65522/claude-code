# 复习本：适配 iPhone 的个人复习网站

纯前端单页应用，不需要后端和账号。数据保存在浏览器的 IndexedDB 里，只在这台设备上。

## 功能

| 功能 | 说明 |
| --- | --- |
| 导入题库 | 支持 JSON、CSV/TSV（Excel 另存为，UTF-8 和 GBK 编码都能识别）、从 Word 或网页复制的文字题目（支持“1.”编号、“A. … B. …”同一行选项、“答案：”“解析：”行、“一、单选题”分节标题）。导入前会预览，逐行列出无法导入的原因；可以新建题库，也可以导入到已有题库，重复题自动跳过。内置示例题库和 CSV、文字、JSON 模板下载。 |
| 题型 | 单选、多选、判断、填空（多个可接受答案用 `|` 隔开，比较时忽略大小写、全角半角和首尾标点）、简答（看参考答案后自己判断对错）。 |
| 答题 | 可以选题库、范围（全部 / 错题 / 没做过的）、顺序（随机 / 按题库顺序）、题量、题型。答完一题立即判分，显示正确答案和解析；可以回看上一题、中途结束。每答一题都会立刻保存，Safari 刷新或关掉页面后可以从首页继续。可选“单选点选即判分”“打乱选项顺序”。 |
| 错题重练 | 答错自动进错题本，记录错误次数和上次的答案。在任何练习里连续答对 N 次（默认 2 次，可设为 1–5）自动移出。支持按题库重练、随机 10 题，以及手动移出、清空。结果页可以一键重练本次错题。 |
| 学习记录 | 累计答题数、正确率、学习天数、连续学习天数、今日数据；最近 14 天的每日柱状图；各题库进度（做过多少、最近一次答对多少、正确率）；练习历史，每次都能打开结果页。 |
| 导出与恢复 | 整份数据导出为 JSON 备份文件（下载、在 iPhone 上通过分享“存储到文件”、或复制文本）。恢复时先预览内容，可以选“覆盖”或“合并”（同一条记录保留较新的）；格式不对或找不到所属题库的记录会被跳过并提示。首页会提醒超过 7 天没有备份。单个题库也能导出成可以再次导入的 JSON。 |
| iPhone 适配 | 安全区（刘海、Home 条）留白、底部标签栏、按钮至少 44pt 高、输入框 16px 以上（避免 Safari 聚焦时自动放大）、深色模式、可以“添加到主屏幕”全屏运行，HTTPS 下离线可用（Service Worker）。 |

## 运行方法

需要 Node.js 18 或更新版本。运行网站本身不需要安装任何依赖。

```bash
cd review-app
npm start            # 等同于 node scripts/serve.js，默认端口 8080
```

- 电脑上打开 <http://localhost:8080>。
- iPhone 和电脑连同一个 Wi-Fi 时，用 Safari 打开启动日志里打印的局域网地址（例如 `http://192.168.1.23:8080`）。换端口：`node scripts/serve.js --port 3000`。
- 局域网的 `http://` 地址能正常使用全部功能，但浏览器只在 HTTPS 或 localhost 下启用 Service Worker，所以这种方式不能离线使用。

**长期在 iPhone 上用（推荐）：** 把 `review-app/` 目录里的文件原样放到任意 HTTPS 静态托管上（GitHub Pages、Cloudflare Pages、Netlify 等，不需要构建步骤）。用 Safari 打开后点“分享 → 添加到主屏幕”，以后从主屏幕图标打开。这样可以离线使用，数据也不会因为 Safari 的“7 天未访问清理网站数据”规则被删。仍然建议定期在“数据”页导出备份。

> 直接双击打开 `index.html`（`file://`）不行，浏览器不允许这样加载 ES 模块，需要用上面的方式启动。

## 题库格式

CSV（第一行是表头，列名中英文都可以，没有题型列时按选项和答案自动判断）：

```csv
题型,题目,选项A,选项B,选项C,选项D,答案,解析,标签
单选,中国的首都是哪座城市？,上海,北京,广州,深圳,B,北京是首都,地理
多选,下列数中哪些是质数？,2,9,11,15,AC,,数学
判断,地球是太阳系中体积最大的行星。,,,,,错,最大的是木星,
填空,一年有____个月。,,,,,12|十二,,
简答,简述番茄工作法。,,,,,专注 25 分钟，休息 5 分钟,,
```

文字（从文档复制）：

```text
一、单选题
1. 中国的首都是哪座城市？
A. 上海  B. 北京  C. 广州  D. 深圳
答案：B
解析：北京是首都。
```

JSON：`{"name":"题库名","questions":[{"type":"单选","question":"…","options":["…","…"],"answer":"B","explanation":"…","tags":["…"]}]}`，也可以直接是题目数组。

## 代码结构

```
index.html, css/app.css, manifest.webmanifest, sw.js, icons/
js/
  importer.js, csv.js   题库解析（JSON / CSV / 文字）、编码识别、校验
  quiz.js               判分、选题、练习进度、错题本规则
  stats.js              学习记录统计
  backup.js             备份文件生成、校验、合并
  db.js                 IndexedDB 和内存两种存储
  store.js              数据层（内存缓存 + 写入存储）
  app.js, ui.js, views/ 页面和路由
scripts/serve.js        零依赖静态服务器
tests/unit/             Node 自带测试运行器
tests/e2e/              Playwright 端到端测试（iPhone 13 尺寸）
```

## 测试

```bash
cd review-app
npm test                       # 单元测试，无需安装依赖
npm install                    # 安装 @playwright/test
npx playwright install chromium   # 首次在新机器上需要下载浏览器
npm run test:e2e               # 端到端测试，会自动启动 127.0.0.1:4173 的服务器
```

### 实际测试结果（2026-10-23，Linux，Node 22.22，Playwright 1.63 + Chromium）

**单元测试：34 个，全部通过**（`npm test`）。覆盖：
- CSV 解析：引号、转义引号、引号内换行、CRLF、BOM、逗号 / 制表符 / 分号
- 题目规范化：各种答案写法（`A,C` `ca` `A、C` 数组、写选项内容），选项的三种写法，类型推断
- 错误提示：缺题目、单选多答案、答案超出选项、选项中间空白、判断答案无法识别、未知题型、选项不足
- JSON、CSV、文字三种导入格式；GB18030 和带 BOM 的 UTF-8 解码
- 每种题型的判分，包括全角数字、末尾句号
- 选题：顺序、可复现的随机、题量、题型、未做优先
- 练习进度和结果统计；错题本的加入、连对计数、移出、再次答错后重置
- 统计：按本地时区分日、连续天数、近 14 天、各题库进度
- 备份：生成、校验（拒绝错误文件，丢弃损坏或孤立的记录并给出提示）、合并规则
- 数据层（内存存储）：导入去重、完整练习流程、刷新后数据仍在、断点续练、简答必须自评、阈值设置、选项乱序后判分正确、覆盖和合并恢复、清空、删除题库保留答题历史

**端到端测试：10 个，全部通过**（`npm run test:e2e`，Chromium 模拟 iPhone 13：390×844、3x 像素比、触摸、iOS UA；每个测试都要求页面没有任何报错）：
1. 载入示例题库 → 按顺序答完 12 题（前 3 题故意答错）→ 结果 9/12、75% → 错题本 3 题 → 两轮全对重练后错题本清空 → 记录页累计 18 题、83%、3 次练习 → 首页今日 18 题和备份提醒
2. 答 2 题后刷新：停留在第 3 题；首页显示“已答 2/12”并能继续；上一题能看到已答结果；放弃后不再提示继续
3. 导入 GBK 编码的 Excel CSV（识别 2 题，第 4 行报错“答案 D 超出了选项范围”）→ 粘贴分节文字题导入到同一题库 → 填空题“h2o”匹配答案“H2O|H₂O”
4. 下载备份（检查文件名和内容数量）→ 清空全部数据 → 用备份文件覆盖恢复（记录和错题都回来）→ 新增题库后粘贴备份合并（两个题库都在）→ 把题库 CSV 当备份恢复会被拒绝
5. 题库重命名、搜索、删除一道题、删除题库
6. 设置刷新后仍保留；关闭“点选即判分”后需要点提交；阈值设为 1 时重练答对一次即移出；中途结束显示“11 题未答”
7. 首页、题库、练习设置、错题、记录、数据、答题页都没有横向滚动；可见的输入框字号不小于 16px；按钮和选项高度不小于 44px；标签栏和答题底栏都在屏幕内
8. 首次访问后断网刷新，页面和数据都能正常显示（Service Worker）
9. 下载 CSV、文字、JSON 模板和导出的题库，再导入都没有错误；重复导入到原题库时全部跳过
10. 打开“打乱选项”后，反馈里的正确答案字母和屏幕上的选项顺序一致，判分正确

**性能抽查（一次性脚本，未放进测试套件）：** 3000 道单选题的 CSV，解析加预览 0.6 秒，写入 IndexedDB 并打开题库页 0.3 秒，冷启动加载全部数据 0.15 秒，开始 3000 题练习 0.14 秒，连续答 20 题并翻页共 2.2 秒（包含自动化操作本身的开销）。

**视觉检查：** 在 iPhone 13 尺寸下截图检查了浅色和深色模式的全部页面；发现并修好了设置开关排版、深色分段控件选中态、浅色模式“上一题”按钮和错题列表顶部多余分隔线的问题。

### 没有测试过的部分

- **真 iPhone 和 Safari（WebKit）没测过。** 这个环境里只有 Chromium，上面所有测试都是 Chromium 模拟 iPhone 屏幕，不是 Safari 本身。下面这些 Safari 特有的行为都没有验证：安全区留白、键盘弹出时底部栏的位置、`添加到主屏幕` 后的全屏模式和图标、Safari 对文件下载的处理（iOS 会弹出下载确认）、7 天清理规则。
- **“导出备份（存储到文件）”按钮没测过。** 它用 `navigator.share` 分享文件，测试用的 Chromium 不支持，所以这个按钮在测试里不会出现。
- **“复制备份内容”按钮没测过**（需要剪贴板权限），**“申请持久存储”和存储用量显示也没测过**。
- **无痕浏览下不能用 IndexedDB 时的内存模式提示没测过**（代码会显示红色提示，关闭页面后数据丢失）。
- Windows 版 Excel 实际另存的 CSV 没测过；测试用的是脚本生成的 GB18030 编码 CSV。
- 中文下载文件名：测试环境的 Chromium 会把中文文件名换成 “download”，所以所有下载文件名改成了英文（如 `review-backup-20261023-1550.json`）。

### 已知限制

- 不能在应用里编辑题目，只能删除后重新导入。
- 文字格式里，如果解析内容自己带“2. …”这样比题号更大的编号，可能会被当成新题；建议解析里不要用数字加点开头。
- 合并恢复时，这台设备上已经移出错题本、但备份里还在的题会重新回到错题本。
- 删除题库后，它的答题历史仍计入“累计答题”，但不再出现在各题库进度里。
