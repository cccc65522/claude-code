# 弈：中国象棋

在浏览器里和电脑下中国象棋，电脑上和 iPhone 上都能用。规则、记谱和对弈引擎都是自己写的，没有用任何第三方库。

## 功能

| 功能 | 说明 |
| --- | --- |
| 对弈 | 和电脑下，可以执红或执黑，五档难度：入门、初级、中级、高级、大师；也可以两个人用同一台设备轮流下。 |
| 走棋 | 点一下棋子，再点目标位置；电脑上也可以直接拖动。能走的位置显示圆点，能吃的子显示红圈。走不了的着法会说明原因，比如“正在被将军，这步不能解将”“这步会让将帅照面”。 |
| 规则 | 完整的中国象棋规则：马腿、象眼、象不过河、炮隔子吃、兵过河后才能横走、将帅不出九宫、将帅不能照面。胜负：绝杀；困毙（无子可动也算输）；60 回合未吃子判和；双方都没有进攻子力判和。重复局面：同一局面第三次出现时，长将判负，长捉（包括一将一捉）判负，长将比长捉重，双方同犯或都不犯判和。 |
| 记谱 | 中文记谱（炮二平五、马8进7、前车退二、中兵平四），点任意一步可以复盘；也可以在输入框里输入着法走棋（中文或 h2e2 这种坐标）。可以复制棋谱和局面（FEN），也可以从任意局面开始。 |
| 电脑 | 悔棋（退回你的上一步）、提示（棋盘上画出建议的箭头）、立即出招、认输。引擎分析面板显示搜索深度、局面评估（如“红优 +0.8”“红方 3 步杀”）、预计的后续着法。开局时会用开局库，显示开局名称（中炮对屏风马、仙人指路、飞相局……）。 |
| 残局练习 | 9 道杀法题，一步杀到三步杀，黑方由电脑防守。做错了可以重来，也可以看电脑演示答案。做对的题会打勾。 |
| 其他 | 自动保存对局（刷新、关掉页面后还在），走子音效（可关），深色模式，可以“添加到主屏幕”离线使用。 |

## 运行方法

需要 Node.js 18 或更新版本。运行网站本身不需要安装任何依赖。

```bash
cd xiangqi
npm start            # 等同于 node scripts/serve.js，默认端口 8080
```

电脑上打开 <http://localhost:8080>；iPhone 连同一个 Wi-Fi 时用 Safari 打开启动日志里的局域网地址。也可以把 `xiangqi/` 目录原样放到任何 HTTPS 静态托管上（比如 GitHub Pages）。

## 引擎是怎么工作的

**棋盘表示**（`js/engine/board.js`）：9×10 的棋盘放在 16×16 的数组中间，走出棋盘就落在填充格上，不用每步判断越界。着法生成先生成“看起来能走”的着法，走完再检查自己的将帅是否被攻击（包括将帅照面），不合法就撤回。检查将军时从将帅出发反查：兵、马（通过马腿反推）、车、炮（隔一个子）、对面的将帅。

走法生成的正确性用 perft 验证：从开局局面数出每一层所有合法着法序列的数量，和公开的标准值逐一比对——第 1 到 5 层分别是 44、1,920、79,666、3,290,240、133,312,995，全部一致。

**估值**（`js/engine/eval.js`）：子力价值加位置分（兵过河、靠近九宫更值钱；马喜欢中路和对方的“卧槽”位置；炮喜欢中路；车喜欢通路和进攻位置）。走子时增量更新，不必每次重新计算整个棋盘。

**搜索**（`js/engine/search.js`）：

- 迭代加深的 alpha-beta 搜索（主要变例搜索 PVS），每加深一层都会更新分析面板；
- 置换表：局面用 Zobrist 哈希表示，算过的局面直接查表；
- 着法排序：置换表着法、吃子（最有价值的目标、最便宜的攻击者优先）、杀手着法、历史表；
- 空着裁剪、后期着法缩减、被将军时延伸一层；
- 静态搜索：搜到深度后继续算吃子，避免在吃子交换的中途下结论；
- 重复局面按象棋规则估值：长将的一方算输；没有长将时，长捉的一方算输；其他重复算和。所以电脑既不会自己走成长捉判负，也会抓住对手长捉的机会；
- 在 Web Worker 里运行，界面始终不卡；
- 难度靠时间、深度和估值扰动区分：“入门”只看两步并且估值带随机误差，“大师”每步算 8 秒。

在开发机的 Node.js 里每秒约搜索 100 多万个局面，开局局面 1 秒左右能算到第 9 层。

**记谱**（`js/engine/notation.js`）：着法转中文记谱，并能把中文记谱解析回着法（支持繁体字、全角数字、“前/中/后”）。开局库就是用中文记谱写的，加载时逐步解析验证。

**残局题**（`js/engine/puzzles.js`）：每道题都用一个独立的穷举程序（`tests/unit/mate-solver.js`，不用剪枝、不用置换表）证明“恰好 N 步能杀、更少的步数杀不了”，引擎在测试里也必须找到同样长度的杀法。这些题是程序随机摆子、再经穷举筛选出来的，不是经典棋谱里的名局。

## 代码结构

```
index.html, css/app.css, manifest.webmanifest, sw.js, icons/
js/
  engine/                不依赖 DOM，Node 里也能跑
    board.js             棋盘、FEN、着法生成、将军检测、Zobrist 哈希、重复局面
    eval.js              子力和位置分
    search.js            搜索引擎和难度设置
    notation.js          中文记谱 / ICCS 坐标的生成与解析
    game.js              一盘棋：着法记录和胜负规则
    book.js              开局库
    puzzles.js           残局题
    worker.js            Web Worker 入口
  ui/
    board-view.js        棋盘绘制（SVG）、棋子动画、点击与拖动
    engine-client.js     与 Worker 通信、立即出招
    ui.js, sound.js      对话框、菜单、提示；合成音效
  app.js                 对局流程、复盘、残局、保存
scripts/serve.js         零依赖静态服务器
tests/unit/              Node 自带测试运行器
tests/e2e/               Playwright 端到端测试（电脑 + iPhone 13 尺寸）
```

## 测试

```bash
cd xiangqi
npm test                 # 单元测试，约 6 秒，无需安装依赖
npm install              # 只有端到端测试需要
npm run test:e2e
```

单元测试：perft（1–4 层）；“捉”的认定（新威胁、发现攻击、有无保护、子力价值、兑子、将帅兵卒例外、未过河兵卒例外）；长捉判负、对有保护的子来回追判和、长将与长捉的轻重顺序；FEN 读写和不合法局面检查；马腿、象眼、炮架、过河兵、九宫、将帅照面；随机对局中的每一个合法着法都能生成中文记谱、记谱各不相同、并能解析回原着法（测试里超过 10 万个）；绝杀、困毙、长将判负、重复判和、无子判和、悔棋；开局库；全部残局题由穷举证明并由引擎解出；能吃到白给的子、不白丢自己的子；不会走成长将判负；会利用对手长捉赢棋；迭代加深的时间控制；增量哈希和估值与重新计算一致。

端到端测试在真实浏览器里：点击和拖动走棋、输入着法、不合法着法的提示、电脑应着、悔棋、提示箭头、执黑时棋盘翻转、复盘、做残局题（成功、失败后看答案）、将死电脑、刷新后对局还在、新局设置；iPhone 尺寸下检查页面没有横向溢出、棋子大小便于点按、点按走棋和解残局。

## 已知限制

- 重复局面实现了长将、长捉（含一将一捉）两条主要的禁止着法，按最近一轮重复来判；正式规则里还有“长杀”“长拦”等更细的条款，以及“捉”的一些特殊情形（比如对方子被牵制时算不算有保护），这里没有全部实现。
- 引擎强度大约是业余水平，和专业象棋程序相比差得多；开局库只有十几条常见变例。
- 残局题不是名局，是程序生成并验证的杀法练习。
